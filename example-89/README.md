# Example 89 - 사용량 계량 + 쿼터 (Punk + Perl)

API 키별로 **호출 수를 세고 한도를 넘으면 `429`** 로 막는 예제입니다. 남은 양을 헤더로
알려주고, 운영자가 한도를 올리거나 사용량을 리셋할 수 있습니다.

- `GET /api/data` → 호출 1회 소모(한도 초과 시 `429`)
- `GET /usage?key=` → 사용량 조회(소모 없음)
- `PUT /quota` → 키 한도 설정
- `POST /quota/reset` → 사용량 리셋
- 키 없으면 `401`, 기간은 **하루 고정 창**

## Routes

| Method | Path            | Description |
|--------|-----------------|-------------|
| GET    | /api/ping       | ping/pong |
| GET    | /api/data       | 계량 대상 (`X-API-Key`) |
| GET    | /usage          | 사용량 조회 |
| PUT    | /quota          | 한도 설정 |
| POST   | /quota/reset    | 사용량 리셋 |

## 동작 방식 (왜 이렇게 될까)

### 사용량은 헤더로 알려준다

호출 성공/실패와 무관하게 남은 양을 헤더로 노출하면 클라이언트가 스스로 속도를 조절할 수
있습니다.

```
X-Usage-Limit: 5
X-Usage-Used: 3
X-Usage-Remaining: 2
```

한도를 넘으면 `429` 와 함께 **언제 다시 시도**하면 좋을지 `Retry-After`(초)를 보냅니다.

### 왜 401 과 429 를 구분하나

- `401` : **키가 없음**(인증 실패) → 클라이언트 잘못
- `429` : 키는 맞지만 **한도 초과** → 잠시 후 재시도

의미가 다르므로 상태코드도 달라야 클라이언트가 다르게 대응합니다.

### 고정 창 vs 슬라이딩 창

여기서는 하루 단위 **고정 창**(`int(time()/86400)*86400`)입니다. 구현이 단순하지만 창
경계에서 몰림(burst)이 생길 수 있습니다. 부드럽게 하려면 슬라이딩 윈도나 토큰 버킷을
씁니다.

```perl
if (($u->{period} // 0) != _period_start()) { $u->{used} = 0; $u->{period} = _period_start(); }
```

### 조회는 소모하지 않는다

`/usage` 는 읽기 전용이라 카운트를 건드리지 않습니다. 그렇지 않으면 사용량을 볼 때마다
한도가 줄어드는 이상한 API 가 됩니다.

### 헤더로 남은 양을 주는 이유

클라이언트가 `429` 를 맞기 전에 스스로 속도를 줄일 수 있어, 재시도 폭주를 막습니다.

## Notes

- 메모리 기반이라 프로세스가 재시작되면 초기화됩니다. 실전은 Redis 등 공유 저장소를 씁니다.
- 분산 환경에선 원자적 증가(`INCR`)와 TTL 을 씁니다.
- 테스트는 401/한도 소모/`429`/조회 무소모/키 격리/한도 상향/리셋/검증을 확인합니다.
