# Example 88 - 시간창 피드 + 커서 페이지네이션 (Punk + Perl)

이벤트를 **시간 범위(since/until)** 로 걸러내고, **키셋 커서**로 안정적으로 페이지를
넘기는 예제입니다.

- `POST /events` → 이벤트 적재(`ts` 옵션, 없으면 서버 시각)
- `GET /feed?since=&until=&limit=&cursor=` → 시간창 + 커서 조회
- 응답: `{ events, count, has_more, next_cursor }`
- `limit` 은 1..100 (벗어나면 `400`)

## Routes

| Method | Path        | Description |
|--------|-------------|-------------|
| GET    | /api/ping   | ping/pong |
| GET    | /api/healthz| k8s liveness |
| GET    | /api/readyz | k8s readiness |
| POST   | /events     | 이벤트 적재 |
| GET    | /feed       | 시간창 + 커서 조회 |
| GET    | /events/:id | 단건 조회 |

## 동작 방식 (왜 이렇게 될까)

### 왜 타임스탬프 페이지네이션인가

`?page=3` 같은 오프셋 방식은 그 사이에 새 이벤트가 들어오면 **항목이 밀리거나 중복**됩니다.
시각 범위와 커서를 쓰면 타임라인을 안정적으로 따라갈 수 있습니다.

### since/until 은 경계 포함

`since <= ts <= until` 로 단순하게 정의합니다. 창이 겹치지 않게 잇고 싶으면 이전 응답의
마지막 `ts` 를 `until` 에 넣고 커서로 중복을 제거합니다.

### 커서 = 마지막 id (불투명 토큰)

`id` 는 단조 증가하므로 "이 id 다음부터" 가 안정적인 키셋입니다. 클라이언트에는
**불투명 토큰**으로 감싸 내부 구조를 숨깁니다.

```perl
sub _encode_cursor { my $s = encode_base64url("$_[0]"); $s =~ s/=+$//; return $s }
```

### 커서에서 패딩(`=`)을 제거한 이유

base64 표준의 `=` 패딩은 **URL 쿼리 파싱에서 문제를 일으킬 수 있습니다**(값에 `=` 가
들어가면 파서에 따라 키/값 경계가 흔들림). 그래서 `=` 를 떼고, 디코드 시 길이로 복원합니다.

```perl
$padded .= '=' x ((4 - length($padded) % 4) % 4);
```

### 조합

시간창 필터와 커서 필터를 **함께** 적용합니다. 그래야 "특정 창 안에서 페이지 넘기기"가
가능합니다.

## Notes

- 커서는 서명하면 위조를 막을 수 있습니다(HMAC). 여기서는 형식 검증만 합니다.
- 아주 큰 피드는 `ts` 인덱스 + `(ts, id)` 복합 커서를 씁니다.
- 테스트는 정렬/커서 3페이지/창 경계/창+커서 조합/검증을 확인합니다.
