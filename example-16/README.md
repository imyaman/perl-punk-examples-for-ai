# Example 16 - 서명 쿠키 세션 (login / me / logout) (Punk + Perl)

로그인 상태를 **HMAC 서명된 쿠키**에 담아 유지하는 세션 예제입니다. 서버 저장소
없이 서명으로 위조를 막습니다.

- `session secret => ..., expires => '7d'` — 세션 활성화
- `$c->session->{user}` 읽기/쓰기 (변경 시 쿠키로 되쓰기)
- `$c->session_expire` 로 로그아웃

## Routes

| Method | Path            | Description |
|--------|-----------------|-------------|
| GET    | /api/ping       | ping/pong |
| GET    | /api/healthz    | k8s liveness |
| GET    | /api/readyz     | k8s readiness |
| POST   | /api/login      | 폼 `user=<name>` → 세션 기록 |
| GET    | /api/me         | 세션의 사용자 조회 |
| POST   | /api/logout     | 세션 만료 |

## 동작 방식 (왜 이렇게 될까)

### 세션 = 쿠키 안의 해시ref

`$c->session` 은 요청 동안 읽고 쓰는 해시ref 입니다. 요청이 끝날 때 **변경이
있었을 때만** JSON 으로 직렬화되어 HMAC-SHA256 으로 서명되고 Set-Cookie 로
나갑니다. 다음 요청에서는 쿠키를 검증해 다시 `%{$c->session}` 으로 복원합니다.

### 서명은 "읽기는 공개, 위조는 불가"

클라이언트는 쿠키 내용을 **읽을 수 있지만 고칠 수는 없습니다**. 서명이 맞지 않으면
그 쿠키는 거부되고 세션은 빈 상태로 시작합니다. 그래서 **비밀값을 세션에 넣으면 안
됩니다** — 서명은 무결성만 보장하고 기밀성은 보장하지 않습니다.

### 상태가 서버에 없다

이 버전은 서버측 저장소가 없습니다. 세션 전체가 쿠키에 실립니다. 그래서 로그인이
서버 메모리를 건드리지 않고도 유지됩니다. 대신 쿠키가 커지면(대략 4KB 초과) croak
하며, 그 지점이 곧 서버측 저장소가 들어갈 자리입니다.

### `session_expire` 는 쿠키 삭제를 지시

로그아웃은 세션을 비우고 쿠키를 지우는 Set-Cookie 를 보냅니다. 이후 요청은
세션이 비어 있어 401 이 됩니다.

### 서명 키는 `secret` 시스템에서

운영에서는 키를 코드에 두지 않고 `secret('session_key')` 처럼 secrets 시스템에서
가져옵니다. 이 예제는 자체 완결을 위해 리터럴 키를 씁니다(실제 배포 금지).

## Notes

- 테스트는 쿠키 jar 로 세션을 이어가며 로그인 → 조회 → 로그아웃을 검증합니다.
