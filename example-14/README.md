# Example 14 - `helper` 로 컨텍스트 메서드 추가 (Punk + Perl)

자주 쓰는 로직을 **`$c->메서드`** 형태로 붙이는 예제입니다. 핸들러마다 유틸
함수를 import 하지 않고, 컨텍스트에 직접 메서드를 설치합니다.

- `helper now_iso => sub { my ($c) = @_; ... }`
- 설치 후 핸들러에서 `$c->now_iso`, `$c->sum(...)` 로 호출

## Routes

| Method | Path            | Description |
|--------|-----------------|-------------|
| GET    | /api/ping       | ping/pong |
| GET    | /api/healthz    | k8s liveness |
| GET    | /api/readyz     | k8s readiness |
| GET    | /api/time       | `$c->now_iso` 로 현재 UTC 시각 |
| GET    | /api/sum/:a/:b  | `$c->sum($a,$b)` 로 합계 |

## 동작 방식 (왜 이렇게 될까)

### helper 는 컨텍스트 클래스에 메서드를 심는다

`helper 이름 => sub {...}` 는 요청 컨텍스트 객체에서 `$c->이름(...)` 으로 부를 수
있는 메서드를 설치합니다. 첫 인자는 항상 `$c` 이고, 그 뒤로 호출 시 넘긴 인자가
이어집니다. 그래서 `$c->sum(2, 3)` 은 `sub { my ($c, @n) = @_ }` 로 들어갑니다.

### 라우트 파라미터와 맞물린다

`/api/sum/:a/:b` 핸들러는 `$c->param('a')` 로 캡처값을 읽고, 그 값을 헬퍼에
넘깁니다. 헬퍼는 컨텍스트에 접근할 수 있으므로 인증 정보(`stash`)·요청 정보까지
자유롭게 쓸 수 있습니다.

### helper vs 전역 서브

- **전역 서브**: `foo()` 로 부르지만 `$c`(현재 요청)에 접근하려면 인자로 넘겨야 함.
- **helper**: `$c->foo()` 로 불러 컨텍스트에 자연스럽게 접근. 테스트에서 `$c` 만
  있으면 되므로 핸들러 코드가 짧아집니다.

### 어디에 두나

헬퍼는 앱 시작 시 한 번 등록됩니다(요청마다 재정의 아님). 공용 유틸은 모듈로 분리해
`helper` 로 등록하는 패턴이 흔합니다.

## Notes

- `sum` 은 데모용으로 인자를 단순 합산합니다(문자열은 수치로 강제).
