# Example 63 - 헤더 기반 멀티테넌시 (Punk + Perl)

모든 요청에서 `X-Tenant-Id` 헤더로 테넌트를 식별하고, **테넌트별로 데이터를 격리**하는
예제입니다.

- 헤더 누락/형식 오류 → `400`
- 목록/생성/조회 모두 테넌트 스코프
- 다른 테넌트의 항목 접근 → `404` (존재 여부를 숨김)

## Routes

| Method | Path        | Description |
|--------|-------------|-------------|
| GET    | /api/ping   | ping/pong |
| GET    | /api/healthz| k8s liveness |
| GET    | /api/readyz | k8s readiness |
| GET    | /tasks      | 테넌트 작업 목록 |
| POST   | /tasks      | 테넌트 작업 생성 |
| GET    | /tasks/:id  | 테넌트 작업 조회 |

## 동작 방식 (왜 이렇게 될까)

### 테넌트 식별

실전에서는 서브도메인, JWT 클레임, 경로 등 다양하지만, 여기서는 **헤더**로 단순화했습니다.
형식(소문자/숫자/하이픈, 1~32자)을 검증해 임의 키 주입을 막습니다.

### 데이터 격리

저장소를 `tenant => [items]` 로 분리해, 쿼리 단계에서부터 테넌트 범위를 벗어나지 않게
합니다.

```perl
my ($rec) = grep { $_->{id} == $id } @{ $DATA{$t} // [] };
```

### 403 대신 404

다른 테넌트의 리소스에 접근하면 `403` 대신 `404` 를 돌려줍니다. `403` 은 "그 리소스가
존재한다"는 사실을 노출하므로, **존재 여부 자체를 숨기는** 편이 안전합니다.

### 주의: 핸들러 반환값

검증 실패 시 반드시 **`$c->json(...)` 의 반환값을 return** 해야 합니다. `$c->json(...)`
을 호출한 뒤 그냥 `return;`(undef) 하면 Punk 는 응답 본문을 `null` 로 덮어씁니다.

```perl
return _bad_tenant($c) unless defined $t;   # OK
```

## Notes

- 메모리 기반이라 재시작 시 초기화됩니다.
- 테스트는 헤더 누락/형식, 격리, 교차 접근 404 를 검증합니다.
